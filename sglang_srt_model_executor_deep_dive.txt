● Here's a comprehensive breakdown of the model_executor/ architecture:

  ---
  Architecture Overview

  The model executor is a 3-tier pipeline:

  ScheduleBatch (CPU/Scheduler)
      ↓
  ModelWorkerBatch (CPU→GPU, TpModelWorker)
      ↓
  ForwardBatch (GPU tensors, ModelRunner)
      ↓
  Graph Runner (CUDA/Piecewise/CPU)

  ---
  Files & Key Classes

  forward_batch_info.py — Central Data Structure

  ForwardBatch is the core GPU tensor container (~300+ fields):
  - input_ids [num_tokens], positions [num_tokens] — flattened across batch
  - seq_lens [batch_size], out_cache_loc [num_tokens] — KV cache pointers
  - forward_mode: EXTEND/DECODE/MIXED/TARGET_VERIFY/DRAFT_EXTEND/IDLE/...
  - capture_hidden_mode: NULL/LAST/FULL — controls if hidden states are captured
  - mrope_positions [3, num_tokens] (Qwen-VL), mamba_track_indices (Mamba SSM),
  spec_info (speculative decoding), pp_proxy_tensors (pipeline parallel)

  Key design: num_tokens = total flattened tokens, batch_size = number of
  sequences.

  ---
  model_runner.py — Main Inference Orchestrator (~3000 lines)

  Decides which runner to use:
  Decode + bs in captured graphs → cuda_graph_runner.replay()
  Prefill + piecewise enabled   → piecewise_cuda_graph_runner.forward()
  CPU mode                       → cpu_graph_runner.replay()
  Else                           → eager model.forward()

  ---
  cuda_graph_runner.py — CUDA Graph Capture/Replay

  - Captures per batch-size (1,2,4,8,16,32,64,128 by default)
  - Pre-allocates GraphInputBuffers once; copies real data at runtime
  - Reverse capture order enables CUDA memory pool sharing
  - Handles capture_hidden_mode variants (must re-capture if mode changes)
  - spec_info: For TARGET_VERIFY, captures num_tokens_per_bs × batch_size total
  tokens

  ---
  piecewise_cuda_graph_runner.py — Prefill torch.compile

  - Not CUDA graphs — uses torch.compile per token-count bucket ([256, 512, 
  1024, ...])
  - Compiles only model.language_model.model (embedder stays eager)
  - Better for variable-length prefill; avoids huge static graphs

  ---
  input_buffers.py — Pre-allocated GPU Buffers

  GraphInputBuffers pre-allocates fixed-size tensors for CUDA graphs:
  - seq_lens_cpu stays on CPU — some attention kernels need CPU access
  - Runtime populate_from_forward_batch() copies actual data + pads remainder
  - num_token_non_padded [1] lets kernels skip padding

  ---
  hook_manager.py — Instrumentation

  Registers nn.Module forward hooks via fnmatch patterns:
  # Pattern: "model.layers.*.mlp" → all MLPs
  register_forward_hooks(model, [{"target_modules": ["model.layers.*.mlp"],
  "hook_factory": "my_mod:make_hook"}])

  ---
  model_runner_kv_cache_mixin.py — KV Cache Sizing

  Computes bytes/token for:
  - MHA: num_kv_heads × (head_dim + v_head_dim) × num_layers × dtype_bytes
  - MLA (DeepSeek): (kv_lora_rank + qk_rope_head_dim) × num_layers × dtype_bytes
   + FP4 scale + NSA indexer overhead
  - Hybrid SWA: weighted sum of full vs. sliding-window layers

  ---
  forward_batch_deepseek_mha_mixin.py — DeepSeek Chunked Prefix Cache

  For long-context DeepSeek MLA: breaks prefix KV cache into 256K-token chunks,
  computing per-chunk attention metadata (starts, seq_lens, cu_seq_lens,
  kv_indices) to stay within memory limits.

  ---
  cpu_graph_runner.py — CPU torch.compile

  Same interface as CudaGraphRunner but:
  - Uses torch.compile(dynamic=False) instead of torch.cuda.CUDAGraph
  - Must register torch.library.register_fake() for custom CUDA ops
  - Only supports dp_size=1, pp_size=1, no TP features

  ---
  mindspore_runner.py — Ascend NPU Init

  Launches MindSpore scheduler subprocess, sets MS_WORKER_NUM/MS_ROLE env vars,
  then calls reuse_hccl_comm() to share NCCL communicators between PyTorch and
  MindSpore.

  token)
          positions if is_decode else seq_lens - 1,
      )
      return next_token_ids
